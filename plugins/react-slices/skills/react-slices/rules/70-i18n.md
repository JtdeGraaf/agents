# Rule: i18n — externalise all copy, keep locales in parity

i18next is set up in `src/i18n/i18n.ts` with locale JSON in `src/i18n/locales/<lang>/translation.json`. One locale is
the default (usually English); every other shipped locale is always complete.

## Every user-facing string is a key

- No hard-coded display text in components/routes — `const { t } = useTranslation()` and `t('group.key')`. This
  includes button labels, headings, placeholders, `aria-label`s, validation messages and `title`s.
- Keys are grouped by area (`nav.*`, `auth.*`, `dashboard.*`, …). Interpolate with `t('k', { name })`.

## Locales stay in lockstep

- Add a key → add it to **every** locale in the same change. Never let one lag "for later."
- Key parity is enforced by a test (`src/i18n/i18n.test.ts`: all locale files have identical leaf-key sets).
- Translation keys are **typed** (an `i18next.d.ts` derives the key union from the default locale), so `t()`
  autocompletes and a typo fails typecheck.

## Backend error messages (the `errors.*` group)

The backend returns a stable `code` (+ positional `args`) on every coded failure; localise it under `errors.<CODE>`.

- **Never throw or hard-fail on a missing translation.** Turn a caught error into copy with a
  `useApiErrorMessage()` hook backed by a pure `localizeApiError` in `lib/api-error.ts`: it maps
  `code → errors.<code>`, interpolates `args`, and **falls back to the backend's English `message`** when no key
  exists yet. That fallback is the point: a newer backend never breaks the UI.
- Interpolate args with i18next **double-brace positional** placeholders — `{{0}}`, `{{1}}`. (A Java backend template
  uses single-brace `{0}` for `MessageFormat`; different engines, don't copy the syntax across.) A translation may
  ignore args it doesn't need.
- The set of `errors.*` keys must match the backend `ErrorCode` enum **exactly**, in every locale — enforced by the
  parity test against the generated error-code enum. After the backend adds a code: regenerate the client and add
  the key everywhere, or the suite fails.

## Language selection

The current language is persisted under an app-prefixed key and toggled via `i18n.changeLanguage(...)`; don't reach
into storage for it directly.

**Self-check:** grep your diff for quoted prose in JSX — it should be `t('…')`, and any new key appears in every
locale file.
