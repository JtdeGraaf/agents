# Rule: Project structure

The app is organised by **responsibility**, not by file type. Each directory under `src/` owns one concern;
dependencies point inward and never reach sideways into another feature's internals.

```
src/
├── routes/        # file-based route modules (thin — wire data + render)
├── features/      # vertical slices (auth, accounts, orders, …): data hooks + feature UI
├── components/    # shared cross-feature UI; components/ui/ = headless-primitive wrappers
├── api/           # client.ts (hand-written: base URL, tokens, interceptors) + generated/ (do not edit)
├── i18n/          # i18next setup + locale JSON
├── lib/           # framework-agnostic helpers and pure logic (cn, config, formatting, derivations)
├── test/          # test setup + MSW handlers
├── main.tsx       # entry: providers (QueryClient → AuthProvider → RouterProvider)
└── routeTree.gen.ts  # generated by the router plugin (committed, do not edit)
```

## Dependency direction

```
routes → features → { api, components, lib, i18n }
features/<a> never imports from features/<b>/internals — share via components/ or lib/
```

- A **new top-level concept** → a new folder under `features/` owning its hooks + components, plus route module(s)
  under `routes/`. Feature folders mirror the backend's feature modules one-to-one.
- Code used by more than one feature moves to `components/` (UI) or `lib/` (logic) — not copied.
- Keep modules small and single-purpose. A file that exports a component **and** unrelated logic should be split
  (this also keeps Fast Refresh working).
- Path alias `@/*` → `src/*`.
