# Rule: UI built in code

All UI is built in code, not scenes, so it is reviewable, diffable and consistent.

- **No inline colours.** Use a named token from `UI/UiTheme` (`UiTheme.Warning`, `UiTheme.TextMuted`). Need a new
  colour? Add a token there first.
- Every UI root sets `Theme = UiTheme.Theme` (built in `UiStyles`). Style with a type variation
  (`ThemeTypeVariation = UiTheme.PrimaryButton`) rather than per-control overrides; a new look is a new variation.
- Distinct contexts (in-game HUD vs menus) may have distinct themes, but each is a token set, not ad-hoc styling.
- Content-driven colours come from content definitions; debug/ghost materials may define their own next to the mesh.
- Overlay labels set `MouseFilter = Ignore` so the HUD never blocks input.
- Key hints shown in more than one place come from one `ControlHints` class, kept in sync with the input map in
  `project.godot`.
- User-facing text that comes from the host is an error code or packet data, formatted client-side — never a string
  the host built.
- Build large control trees in small private `Build…()` methods returning the container.
- Fonts are bundled with their licences.
